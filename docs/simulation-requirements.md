# サッカーシミュレーションプログラム 基本要件レポート

> このレポートは、`futsal-sim` プロジェクトのコードベース（`engine.ts`, `constants.ts`, `types.ts`, `Home.tsx`, `headless-sim.ts`, `cardData.ts`）を直接解析して作成したものです。初めてこのプロジェクトに参加する開発者・分析者が全体像を把握できるよう、アーキテクチャから数値パラメータまでを体系的に記述します。

---

## 1. プロジェクト概要

本プログラムは、**11対11のサッカーシミュレーター**です。プロジェクト名は `futsal-sim` ですが、実装はフルサイズのサッカーコート（105m × 68m）を使用した 90分制の試合シミュレーションです。フロントエンドは React 19 + TypeScript で構築されており、ゲームエンジン部分はブラウザ上の Canvas 2D レンダリングと、Node.js 上で動作するヘッドレスシミュレーションの両方で共用されます。

## 3. ゲームエンジンの仕組み

### 3.1 試合の基本構造

1試合は **前半・後半それぞれ 120 シミュレーション秒**（合計 240 秒）で構成されます。この 240 秒がゲーム内の「90分」に対応します。試合時計の換算式は以下の通りです。

```
matchClock（分） = (simTimeInHalf / 120) × 45
```

ハーフタイムには 3 秒のポーズが入り、後半開始時に全選手の左右が反転します（攻撃方向が入れ替わる）。

### 3.2 ゲームループの構造

ブラウザ上では `requestAnimationFrame` を使ったループが毎フレーム（約 60fps）実行されます。各フレームで `update(st, dt)` を複数回呼び出す「サブステップ」方式を採用しており、速度モードに応じてサブステップ数が変わります。

```
rawDt = min(実経過時間, 0.05秒)   // フレーム時間（上限 50ms）
subSteps = VFAST: 8, FAST: 4, MID: 2, それ以外: 1
dt = rawDt / subSteps             // 各サブステップへの入力
```

`update()` 内では `dt` を受け取り、以下の 2 種類の時間スケールに分離します。

```
physDt = dt                         // 物理演算用（speedMul 非依存）
dt     = physDt × PHYS_SCALE(10.8) // 実際の物理 dt（全モード共通）
simDt  = physDt × speedMul         // 試合時計の進み（speedMul 依存）
```

この設計（v11.36.0 以降）により、**物理演算の精度は全速度モードで同一**となり、速度モードは「試合時計の進み方」と「サブステップ数」にのみ影響します。

### 3.3 速度モードとフレーム数

速度モードは 6 段階あり、`speedMul` の値が試合時計の進み速度を決定します。

| モード | speedMul | 実時間/試合 | フレーム数/試合 | ゴール数/試合（実測平均） |
|---|---|---|---|---|
| REAL | 0.0444 | 約 90 分 | 約 324,000 | — |
| VSLOW | 0.10 | 約 40 分 | 約 144,000 | — |
| LOW | 0.15 | 約 27 分 | 約 96,000 | — |
| MID | 0.40 | 約 7.5 分 | 約 36,000 | 約 20 |
| FAST | 1.0 | 約 4 分 | 約 14,400 | 約 8.6 |
| **VFAST** | **2.0** | **約 2 分** | **約 7,200** | **約 4.0** |

**フレーム数とゴール数は比例関係にあります**（詳細は別レポート「フレーム数が試合結果に与える影響」を参照）。ヘッドレスシミュレーションは VFAST モードで固定実行されるため、MID モードで観戦した場合と比較して約 5 倍のゴール数差が生じます。

## 5. 物理演算

### 5.1 ボールの物理

ボールは 2D 平面上の位置（`pos`）と速度（`vel`）に加え、**Z 軸（高さ）**と**スピン**を持ちます。

| パラメータ | 説明 |
|---|---|
| `ball.z` | ボールの高さ（m）。ロングパスやシュートで上昇 |
| `ball.vz` | 垂直速度（m/s）。重力で減衰 |
| `ball.spinX` | サイドスピン（rad/s）。カーブの原因 |
| `ball.spinY` | トップ/バックスピン（rad/s） |
| `looseBallDrag` | ルーズボールの減速係数（3.5） |

ロングパスは常にロブ（浮き球）として扱われ、Z 軸の動きが発生します。シュートは `shotSpeed`（30 m/s）で蹴り出され、`shotAccuracy`（0.58）に基づいてランダムな誤差が加わります。

### 5.2 足システム（v8.9.0）

各選手は**左右の足**を独立したオブジェクトとして持ちます。足の位置はボディセンターから最大 0.4 m の範囲内に制約され、足からボールまでの距離が遠いほどキック精度が低下します。利き足と逆足では精度が異なり、`weakFootAccuracy`（0〜10）で調整されます。背番号 10 の選手は両足が均等に使えるよう設定されています（`weakFootFreq = 8`, `weakFootAccuracy = 8`）。

### 5.3 GK セーブ判定

GK のセーブ判定は以下の要素を組み合わせた確率計算で行われます。

```
saveChance = min(0.95, gkSaveBase + angleBonus + distBonus)
```

| 要素 | 値 | 説明 |
|---|---|---|
| `gkSaveBase` | 0.30 | 基本セーブ率（v11.32.1 で 0.45 → 0.30 に引き下げ） |
| `gkSaveAngleBonus` | 最大 0.15 | 正面からのシュートほど高い |
| `distBonus` | 最大 0.80 | 遠距離シュートほど高い（12m=0, 27m=+0.80） |
| `gkSaveRadius` | 0.9 m | セーブ判定の基本半径 |

セーブ成功時は「キャッチ」か「パンチング」かを確率的に決定します。速いボール・バウンド直後・無回転ボールはキャッチしにくくパンチングになりやすい設計です。

## 6. AI の仕組み

### 6.1 AI 判断の基本構造

各選手は `decisionInterval`（0.25 秒）ごとに AI 判断を実行します。ボールを保持している場合は `decideHasBall()`、保持していない場合は `decideNoBall()` が呼ばれます。

**ボール保持時の優先順位（`decideHasBall`）:**

1. **シュート優先**: ゴールまで 27m 以内かつ適切な角度であればシュートを選択
2. **前方キャリー**: ゴールへの進路が空いている場合はドリブルで前進
3. **パス判断**: 最適なパスターゲットをスコアリングして選択
4. **ロングパス**: ワイドプレイヤーへのロングパスを検討
5. **ドリブル**: パスも困難な場合はドリブル突破を試みる

**パスターゲットのスコアリング要素:**

| 要素 | 説明 |
|---|---|
| 受け手の前方スペース | 受け取り後にさらに前進できるか |
| パスレーンの開放度 | 相手選手に遮られていないか |
| プレッシャー回避 | 自分が相手に囲まれている場合は優先度アップ |
| 逆サイドへの展開 | サイドチェンジによる打開 |
| アンチピンポン | 直前のパス元への折り返しを抑制 |

### 6.2 オフサイド判定

オフサイドは有効化されており（`offsideEnabled: true`）、相手の最終ラインより 0.25 m 以上前にいる受け手へのパスはオフサイドと判定されます。オフサイド時は 1.2 秒の試合停止が発生します。

### 6.3 スタミナシステム

各選手は短期スタミナ（`staminaShort`）とバーストタイマー（`burstT`）を持ちます。スタミナが低下すると移動速度が低下し、バーストクールダウン（`burstCD`）が経過するまで瞬発的な加速ができなくなります。

## 7. セットプレー

以下のセットプレーが実装されています。

| セットプレー | トリガー条件 | アニメーション |
|---|---|---|
| スローイン | ボールがタッチライン外に出た場合 | テイカーが走り寄り、助走・投球モーション |
| コーナーキック | ボールがゴールラインを越えた場合（守備側が最後に触れた） | テイカーがコーナーに走り寄り、キックモーション |
| ゴールキック | ボールがゴールラインを越えた場合（攻撃側が最後に触れた） | GK がゴールエリア内からキック |
| フリーキック | タックル時のファウル（18%）またはドリブル時のファウル（10%） | 壁（3人）形成後、直接シュートまたはパス |

セットプレーのアニメーションは「walk → setup → windup → kick → done」の 5 フェーズで構成されます。

## 9. ゴールリプレイシステム（v11.0.0）

ゴールが決まると、直前 5 秒間のフレームデータが保存され、ゴール後に自動的にリプレイが再生されます。リプレイは 30fps で記録され、各フレームには選手位置・ボール位置・スコア・試合時計が含まれます。リプレイ終了後は 5 秒間の自動スキップカウントダウンが表示されます。

## 11. ヘッドレスシミュレーション

`headless-sim.ts` は Node.js 上で 100 試合を一括実行し、統計データを JSON ファイルに出力するツールです。

| 設定項目 | 値 |
|---|---|
| 速度モード | VFAST（固定） |
| フレームレート | 60fps（`SIM_DT = 1/60`） |
| 試合数 | 100 試合 |
| フォーメーション組み合わせ | 4-4-2 / 4-2-3-1 / 3-4-3 をローテーション |
| 出力ファイル | `sim_matches.json`, `sim_shots.json` |

ヘッドレスは VFAST で実行されるため、**ゲーム画面で MID モードを使用した場合と比較して約 5 倍のフレーム差が生じ、ゴール数も約 5 倍の差になります**。ゲーム画面との統計比較を行う際は、必ず同じ速度モードで実行する必要があります。

## 12. 既知の課題と注意事項

| 課題 | 内容 | 影響 |
|---|---|---|
| 速度モードによるゴール数差 | フレーム数がゴール数に比例するため、速度モードによって統計が大きく変わる | ヘッドレスとゲーム画面の比較時に要注意 |
| ゴールリプレイ中のボタン操作 | リプレイ表示中は V.FAST ボタンが効かない場合がある | 速度変更が反映されないまま試合が進む可能性 |
| GK セーブ率の調整履歴 | v11.32.1 で `gkSaveBase` を 0.45 → 0.30 に引き下げ済み | 過去バージョンとの統計比較に注意 |
| シュート射程の調整履歴 | v11.31.0 で `shotRange` を 38m → 27m に縮小済み | 過去バージョンとの統計比較に注意 |
